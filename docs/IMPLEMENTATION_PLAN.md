# 学習設計と実装計画

対象：ネットワーク工学、信頼性工学、性能評価、構成管理。学習設計は観測・予測・実験・説明・転移を一周させる。

|段階|達成目標|操作と証拠|判定|
|---|---|---|---|
|既存18課題|層を区別して調査・修復する|実コマンドに近い入力、履歴、予想メモ|従来の機能条件、変更後の再観測|
|プロトコル|DNS/TCP/HTTPの成功範囲を区別|結果の予測→異なる条件で再回答|選択根拠の解説と客観判定|
|キャプチャ|SYN再送とRST応答の違いを証拠から読む|tcpdump絞り込み、パケット詳細、原因仮説|観測済み＋根拠に整合する診断|
|HA設計|接続だけでなく単一機器/共通障害に耐える|配線変更、機器停止、故障ドメイン分離|すべての対象故障でサービス継続|
|FW/VPN|必要通信の許可と不要通信の拒否|ゾーンポリシー、トンネル、正負テスト|要件全件、再検証必須|
|性能と拡張|ボトルネックを実測モデルで特定|リンク帯域・サーバー増設、負荷変更|平常/増加負荷の容量と予算制約|
|Netplan|宣言を検証しロールバックを経験|YAML編集、generate/try、確認/取消|正しいアドレス・経路・DNS、再検証|
|Ansible|差分を確認して冪等に適用|Playbook編集、check/diff、2回適用|対象2台＋2回目changed=0|
|Terraform|planとapplyを分け、状態差分を管理|HCL編集、保存plan、apply、drift|2 AZのsubnet、driftの再計画と復旧|

## UI/UXの改修
- 調査モードを既定にする。機器の実体と配線は残し、未観測の内部状態と自動解説は隠す。
- 機構解説は明示的に開く。ヒントの使用を罰しないが、使用記録と自力の達成を区別。
- 達成条件は隠さない。操作の正解列と条件を分離。
- 予想メモ、ログ、結果を保持。設定変更は観測の鮮度を失効させる。
- 復習は任意に開ける。操作中に強制的な解説モーダルを出さない。
- 発展工房は独立して開始可能。既存セーブを壊さない。

## 実装境界
ブラウザ内の限定的な状態モデル。実Linux、実pcap取得、暗号処理、クラウドやAnsibleの実行はしない。
コマンドの未対応構文を成功扱いにしない。性能値はモデル計算であり実測値ではない。
HAでは転送可能なグラフを使い、STP/VRRP/OSPFの収束・セッション同期は扱わない。
IaCは画面に提示した小さな構文のみ。実機用ファイルとしての保証はしない。

## 検証
純粋関数の回帰テスト、誤答/未観測/変更後の失効、全設計課題の解法、IaCの不正入力・冪等性・ロールバック、ブラウザの操作とレイアウト。
学習効果そのものは未検証。今後、未知課題の正答率・必要ヒント・根拠の説明を使い評価する。

## 実装・検証結果
- 基礎18課題の調査表示・任意解説・調査ノート・任意の転移問題を実装。
- 発展工房の8課題を実装し、ブラウザで全8課題の達成経路を通過。
- 自動テスト49件成功。HAの共通電源障害、帯域上限、予算超過、キャプチャ不正構文、IaCの不正構文・未検証状態・冪等性・drift・古いplan・試験取消を確認。
- 評価の限界：実機互換試験と学習者による効果測定は未実施。発展工房のIaCは全トポロジの自動生成とは独立した限定演習で、任意のPlaybook/HCL/YAMLには対応しない。
